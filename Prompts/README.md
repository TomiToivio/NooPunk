# NoöPunk author prompt archive

This directory preserves **Tomi's substantial original NoöPunk design and development prompts** for later reference and reuse, including proposals that were abandoned, superseded or never implemented. It covers Story, Simulator and RPG together. It is **not** a transcript of everyday commands, a task tracker or a source of established canon.

## Mandatory procedure for every agent

1. For each incoming author prompt, ask whether it **clearly** concerns NoöPunk Story, Simulator or RPG; contains substantial original worldbuilding, theory, rules, narrative, design or development ideas; and is long and carefully composed. **If yes, archive it proactively.** This is a qualitative threshold, not a fixed word count.
2. **Do not archive** short instructions such as “do this”, “fix this”, merge requests, status checks, routine debugging prompts, casual film recommendations, unrelated project prompts or your own response text.
3. Before creating a file, search this directory by **date, topic and distinctive phrases**. Also look for previously saved copies elsewhere in the repository. Do not duplicate an existing entry. Rename an existing misnamed copy to the standard path, preserving its original content and, if possible, its history; never overwrite a distinct prompt.
4. Use `Prompts/DD_MM_YYYY_TOPIC_NAME.md`, where the date is the date of the **original prompt** and the topic is concise, descriptive and uppercase with underscores. For distinct same-day prompts on a similar topic, use descriptive filename suffixes.
5. Write **human-readable Markdown**: heading, original date, topic, source context, and **the author's actual original prompt**. Preserve wording, detailed concepts, examples, links, uncertainty and original language. Normalize transport formatting only (e.g. HTML escapes); avoid editorial rewriting. Distinguish archival metadata from original text.
6. For follow-up variants, preserve each original version or clearly labeled dated amendments; never silently rewrite earlier ideas to fit current canon. Do not promote archived ideas to current requirements without explicit authorization.
7. Exclude secrets, credentials and unrelated private data from the public archive. Note any necessary redactions. Do not archive material inaccessible to the agent or hallucinate a reconstructed original.
8. Commit or include the archive alongside the qualifying prompt's normal work when feasible and link it in the related issue or PR. This **documentation-only procedure does not override any development scope freeze** or permit work on currently inactive subprojects.
