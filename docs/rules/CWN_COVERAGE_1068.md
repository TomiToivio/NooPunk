## Gaps, with the reason recorded next to each

- **Final Steps** (`partial`) — Derived numbers (HP, saves, attack bonus) and contacts are implemented. The starting-credits / equipment-package step has no procedure: a starting character's purse is a table decision in this implementation.
- **Special Combat Maneuvers** (`missing`) — The SRD section covers shoving and grappling (opposed Str/Punch, prone, escape, forced movement), the two-weapon penalty and execution attacks. No procedure in src/rules implements any of them and no test names them; filling this needs new code, not a re-reading of existing code.
- **Armor Accessories** (`partial`) — Armour pieces and armour mods are implemented; the SRD's separate accessory items (comms, vision, environment gear) are not modelled as their own catalogue.
- **Cyberdoc Tools** (`partial`) — Theatre grade 0 models 'a cyberdoc kit and nothing else' as the -1 row; there is no separate cyberdoc-tool catalogue with weights and prices.
- **Cyberdecks** (`partial`) — The deck bonus feeds the access pool and deck mods are supported; the SRD's cyberdeck hardware catalogue (models, prices, slots) is not modelled.
- **Node Links** (`partial`) — The module documents the wireless-link penalty and refuses to ship a node graph the author has not ruled on; node-to-node links and their verb costs are therefore not implemented.
- **Antagonists** (`partial`) — NPC reaction and morale are implemented. The SRD navigation this audit walks omits the Antagonists chapter, so stat blocks cannot be audited without the Free Edition PDF. Recorded, not claimed.

## No CWN core rule was modified

This audit adds documentation, a traceability file and one new module (`src/rules/cwn_lifestyles.py`, covering a section that had no implementation). It changes no existing CWN procedure: `data/rules/cwn_baseline_sha256.json` pins the SHA-256 of every `src/rules/cwn_*.py` file, and `tests/test_cwn_traceability_1068.py` fails if one of them changes. Changing a CWN rule therefore cannot happen silently — it fails CI and requires the baseline to be re-pinned in a PR that says so.

## How the two-way parity is enforced

The rules side is enforced in CI: the matrix is regenerated by the audit tool and compared (`tools/cwn_parity_audit.py --check`), and the curated evidence is checked against the code. The tabletop side is a documentation claim, and `AGENTS.md` §271 forbids CI assertions over Markdown prose, so it is enforced by the PR checklist instead: a rules change must update `rulebook/` and `data/rules/cwn_traceability.json`'s `rulebook` column in the same PR. That is a deliberate, stated limitation of this mechanism, not an oversight.
